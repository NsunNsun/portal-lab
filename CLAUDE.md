# CLAUDE.md — Лаборатория нестабильных порталов

Конституция проекта. Читается в начале каждой сессии. Если правишь поведение
домена — правь и этот файл. **Актуальная версия механики — 2.**

## Что это и для кого

Веб-приложение «Лаборатория нестабильных порталов» — панель смотрителя, который
следит за магическими порталами и принимает по ним решения: разведать,
стабилизировать, спасти и эвакуировать существ, закрыть, пометить как сомнительный.
Пользователь — дежурный смотритель лаборатории. Задача приложения: показать
состояние порталов, понятно объяснить оценку риска (в том числе честно сказать
«данных нет») и не дать совершить опасное действие вслепую.

Интерфейс — на русском. Код, коммиты, идентификаторы — на английском.

## Модель данных

- **Portal** — `id`, `name`, `world`, `energy` (0..100), `stability` (0..100),
  `hoursToCollapse` (0..72), `creaturesInside` (0..N), `status`, `observerSent`,
  **`surveyed`** (разведан ли портал), **`rescuerSent`** (внутри спасатель),
  `history: HistoryEntry[]`.
- **HistoryEntry** — `id`, `at`, `message`. История изменений конкретного портала.
- **LogEntry** — общий журнал: `id`, `at`, `portalId`, `portalName`,
  `kind: 'action' | 'blocked' | 'system'`, `message`.
- **AppState** — `portals`, `log`, `datasetKey`.

Типы — единственный источник правды: `src/domain/types.ts`.

## Статусы портала

- `open` — открыт, работает штатно.
- `questioned` — помечен смотрителем как сомнительный (переключается вручную).
  Закреплён вверху списка.
- `closed` — закрыт (вручную или схлопнулся). Риск 0, действий не принимает,
  кроме отказа с причиной.

Отдельно от статуса: **`surveyed: false`** — портал не разведан. Его энергия,
стабильность и содержимое неизвестны, риск не считается (уровень `unknown`).
Разведать = отправить наблюдателя (`sendObserver` выставляет `surveyed = true`).

## Формула риска (`src/domain/risk.ts`)

Порядок проверок в `computeRisk`:

1. `surveyed === false` → `{ known: false, level: 'unknown' }`, счёт не считается.
2. `status === 'closed'` → `{ known: true, score: 0, level: 'none' }`.
3. Иначе считаем базу и последовательные факторы.

**База** — три взвешенных компонента, каждый нормирован в 0..100:

| Компонент    | Значение                                            | Вес |
|--------------|-----------------------------------------------------|-----|
| instability  | `100 - stability`                                   | 0.5 |
| energyLoad   | `energy`                                            | 0.3 |
| timePressure | `clamp(100 - (hoursToCollapse / 48) * 100, 0, 100)` | 0.2 |

`base = 0.5*instability + 0.3*energyLoad + 0.2*timePressure`

**Факторы применяются ПОСЛЕДОВАТЕЛЬНО.** Каждый приближает риск к 100 на свою
долю остатка: `risk = risk + (100 - risk) * k`.

1. Время (взаимоисключающие, применяется один):
   - `hoursToCollapse <= 2` → `k = 0.45` «Портал вот-вот схлопнется»
   - иначе `hoursToCollapse <= 6` → `k = 0.20` «Осталось меньше 6 часов»
2. `stability < 20` → `k = 0.35` «Критическая нестабильность»
3. `lives = creaturesInside + (observerSent?1:0) + (rescuerSent?1:0)`;
   `lives > 0` → `k = min(0.30, 0.08 + 0.04 * lives)` «Внутри живые».
   Живые — это существа **и люди внутри** (наблюдатель, спасатель).

Итог: `score = clamp(round(risk), 0, 100)`.
Пороги: **0–29 low**, **30–59 medium**, **60–84 high**, **85–100 critical**.

`computeRisk` возвращает полный разбор для интерфейса:
`{ known, score, level, parts, base, steps, dominant }`.
`steps` содержит и НЕприменённые факторы (`applied: false`) — интерфейс
показывает их приглушённо с пометкой, почему не сработали. `dominant` — фактор
с наибольшим `delta` (или `null`, если ни один не применился).

Жёстких потолков `max(85)` больше нет — риск реагирует на действия пользователя
(стабилизация реально снижает счёт).

## Матрица действий и причины отказов (`src/domain/rules.ts`)

`checkAction(portal, action)` → `{ allowed:true }` | `{ allowed:true, confirm }` |
`{ allowed:false, reason }`. Тексты причин — user-facing, менять осторожно.

| Действие          | Отказ / подтверждение |
|-------------------|-----------------------|
| `stabilize`       | closed → «Портал закрыт — стабилизировать нечего.»; `!surveyed` → «Параметры портала неизвестны. Сначала отправьте наблюдателя.» |
| `close`           | closed → «Портал уже закрыт.»; `!surveyed` → confirm «Портал не разведан: неизвестно, есть ли внутри живые. Закрыть вслепую?»; иначе если внутри существа/наблюдатель/спасатель → confirm, перечисляющий всех: «Внутри портала существ: N. Внутри наблюдатель. Внутри спасатель. Они останутся в мире назначения. Закрыть?» (только верные фразы) |
| `sendObserver`    | closed → «Нельзя отправить наблюдателя в закрытый портал.»; observerSent → «Наблюдатель уже находится внутри.»; **разведанный** критический → «Риск критический (N из 100). Отправлять наблюдателя запрещено регламентом.» Для неразведанного отправка РАЗРЕШЕНА (разведка вслепую). |
| `recallObserver`  | `!observerSent` → «Наблюдателя внутри нет.»; closed → «Портал закрыт.» |
| `sendRescuer`     | closed → «Нельзя отправить спасателя в закрытый портал.»; `!surveyed` → «Портал не разведан: неизвестно, есть ли внутри кого спасать.»; rescuerSent → «Спасатель уже внутри.»; creaturesInside=0 → «Внутри нет существ — спасать некого.»; критический → «Риск критический (N из 100). Отправлять спасателя запрещено регламентом.» |
| `recallRescuer`   | `!rescuerSent` → «Спасателя внутри нет.»; closed → «Портал закрыт.» |
| `evacuate`        | closed → «Портал закрыт.»; `!surveyed` → «Портал не разведан.»; creaturesInside=0 → «Внутри нет существ — эвакуировать некого.»; `!rescuerSent` → «Внутри нет спасателя. Сначала отправьте спасателя.» |
| `toggleQuestioned`| closed → «Портал закрыт — пометка не имеет смысла.» |

Проверки правил живут в reducer, а не только в UI: интерфейс не может обойти
запрет; запрещённые действия кликабельны, приглушены и логируются как `blocked`.

## Эффекты действий (`src/domain/reducer.ts`)

- `stabilize` → `stability = min(100, +25)`, `energy = max(0, -10)`
- `close` → `status = 'closed'`, `observerSent = false`, `rescuerSent = false`
- `sendObserver` → `observerSent = true`, `surveyed = true`. Если портал был
  неразведан — дополнительная запись в `history`:
  «Разведка проведена: энергия X, стабильность Y, существ внутри Z».
- `recallObserver` → `observerSent = false`
- `sendRescuer` → `rescuerSent = true`
- `recallRescuer` → `rescuerSent = false`
- `evacuate` → `creaturesInside = 0`, `rescuerSent = false`; запись
  «Эвакуировано существ: N. Спасатель вышел вместе с ними.»
- `toggleQuestioned` → `open ↔ questioned`

Каждое разрешённое действие → запись `kind:'action'` в общий журнал **и** запись
(или несколько) в `history` портала. Запрещённое → портал не меняется, запись
`kind:'blocked'` с текстом причины.

`advanceHour(state)` — у всех незакрытых порталов `hoursToCollapse = max(0, -1)`,
`stability = max(0, -3)`. Запись в `history` каждого портала:
- если внутри наблюдатель — подробная телеметрия: «Час прошёл. Стабильность 45→42,
  энергия 75, до схлопывания 12→11 ч, риск 65→67.»;
- иначе короткая: «Час прошёл.».
Портал с `hoursToCollapse === 0` → `closed`, флаги `observerSent`/`rescuerSent`
сбрасываются, системная запись в журнал «Портал схлопнулся. Внутри оставались:
существ N, наблюдатель, спасатель.» (перечисляются только те, кто был). Одна
системная запись «Прошёл час».

`loadDataset(key)` — заменяет порталы набором, очищает журнал, пишет системную
запись о загрузке.

## Рекомендации (`src/domain/recommend.ts`)

`recommendAction(portal)` → `{ text, action }`, ведёт по всему жизненному циклу:

- closed → «Действий не требуется», `null`
- `!surveyed` → «Отправить наблюдателя для разведки», `sendObserver`
- существа внутри:
  - спасатель внутри → «Эвакуировать существ», `evacuate`
  - critical/high → «Стабилизировать портал перед спасением», `stabilize`
  - иначе → «Отправить спасателя за существами», `sendRescuer`
- без существ: critical → `close`; high → `stabilize`;
  внутри наблюдатель/спасатель → «Существ нет — закрыть портал», `close`;
  medium → «Отправить наблюдателя», `sendObserver`; low → «Оставить открытым».

## Сортировка (в представлении, `src/ui/PortalsTable.tsx`)

Три уровня: (1) `questioned` — закреплены сверху; (2) `surveyed === false` —
неразведанные; (3) остальные по убыванию риска. При равенстве — по названию.

## Интерфейс — ключевые правила

- Выход из карточки: крестик в правом верхнем углу, `Esc`, повторный клик по
  выбранной строке снимает выбор; после снятия возвращается блок «Смена началась».
- Неразведанный портал: в таблице энергия/стабильность/существа — «—», риск —
  «? Нет данных» приглушённо; в карточке блок «Данные недоступны» с кнопкой
  «Отправить наблюдателя».
- Разбор риска — цепочка: таблица трёх показателей и «База: N», затем факторы по
  порядку (доля %, было → стало, прирост), неприменённые приглушены; «Итог: N».
  Под крупным числом — «Больше всего добавляет: <фактор> (+N)» или «Риск
  определяется базовыми показателями».
- Бейджи «Набл.» и «Спас.» рядом с названием портала (текст в рамке, не эмодзи).
- Шесть кнопок действий (сетка 2×3); кнопки наблюдателя/спасателя переключаются
  между «Отправить» и «Отозвать».
- Сводка — семь плиток: Открыто · Критических · Требуют внимания · Без данных ·
  Под вопросом · Закрыто · Существ внутри. Неразведанные не считаются
  критическими/требующими внимания; наблюдатель и спасатель — не «существа».

## Архитектурные решения

- **Доменный слой без React.** `src/domain/*` — чистые функции, тестируются в `node`.
- **Проверка правил в reducer, а не только в UI.** Запрет нельзя обойти.
- **Состояние только в памяти.** Нет localStorage, бэкенда, сети.
- **Время не тикает само.** Часы двигаются только через `advanceHour`.
- **Демо-данные детерминированы.** Без `Date.now()` и случайностей в `datasets.ts`.
  `Date.now()`/счётчик id — только в reducer для runtime-записей журнала.
- **Никаких секретов.** Ни API-ключей, ни `.env`.

## Правила кода

- TypeScript строгий (`strict`, `noUncheckedIndexedAccess`, `noUnusedLocals` и т.д.).
- Доменная логика — чистыми функциями (кроме id/времени в reducer).
- Интерфейс — на русском; код, идентификаторы, коммиты — на английском.
- Коммиты — осмысленные, в повелительном наклонении, по блокам.
- Никаких лишних зависимостей.
