# CLAUDE.md — Лаборатория нестабильных порталов

Конституция проекта. Читается в начале каждой сессии. Если правишь поведение
домена — правь и этот файл.

## Что это и для кого

Веб-приложение «Лаборатория нестабильных порталов» — панель смотрителя, который
следит за магическими порталами и принимает по ним решения: стабилизировать,
закрыть, отправить наблюдателя, пометить как сомнительный. Пользователь —
дежурный смотритель лаборатории. Задача приложения: показать состояние порталов,
понятно объяснить оценку риска и не дать совершить опасное действие вслепую.

Интерфейс — на русском. Код, коммиты, идентификаторы — на английском.

## Модель данных

- **Portal** — `id`, `name`, `world`, `energy` (0..100), `stability` (0..100),
  `hoursToCollapse` (0..72), `creaturesInside` (0..N), `status`, `observerSent`,
  `history: HistoryEntry[]`.
- **HistoryEntry** — `id`, `at`, `message`. История изменений конкретного портала.
- **LogEntry** — общий журнал: `id`, `at`, `portalId`, `portalName`,
  `kind: 'action' | 'blocked' | 'system'`, `message`.
- **AppState** — `portals`, `log`, `datasetKey`.

Типы — единственный источник правды: `src/domain/types.ts`.

## Статусы портала

- `open` — открыт, работает штатно.
- `questioned` — помечен смотрителем как сомнительный (переключается вручную).
- `closed` — закрыт (вручную или схлопнулся). Закрытый портал имеет риск 0 и
  не принимает действий, кроме отказа с причиной.

## Формула риска (`src/domain/risk.ts`)

Закрытый портал: `score = 0`, `level = 'none'`, без разбора.

Для незакрытых — три взвешенных компонента, каждый нормирован в 0..100:

| Компонент     | Значение                                          | Вес |
|---------------|---------------------------------------------------|-----|
| instability   | `100 - stability`                                 | 0.5 |
| energyLoad    | `energy`                                          | 0.3 |
| timePressure  | `clamp(100 - (hoursToCollapse / 48) * 100, 0, 100)` | 0.2 |

`base = 0.5*instability + 0.3*energyLoad + 0.2*timePressure`

Жёсткие модификаторы (применяются поверх base, в этом порядке):

- `stability < 20` → `risk = max(risk, 85)` (критическая нестабильность перевешивает всё)
- `hoursToCollapse <= 2` → `risk = max(risk, 85)` (портал вот-вот схлопнется)
- `creaturesInside > 0` → `risk = risk + 5`

Итог: `round`, затем `clamp(0, 100)`.

Пороги уровней: **0–29 low**, **30–59 medium**, **60–84 high**, **85–100 critical**.

`computeRisk` возвращает не только число, но и разбор (`parts`, `modifiers`) —
интерфейс обязан уметь объяснить, откуда взялась цифра.

## Матрица действий и причины отказов (`src/domain/rules.ts`)

`checkAction(portal, action)` → `{ allowed:true }` | `{ allowed:true, confirm }` |
`{ allowed:false, reason }`. Тексты причин — user-facing, менять осторожно.

| Действие          | Запрет                                                    | Подтверждение |
|-------------------|-----------------------------------------------------------|---------------|
| `stabilize`       | closed → «Портал закрыт — стабилизировать нечего.»        | —             |
| `close`           | closed → «Портал уже закрыт.»                             | существа внутри → «Внутри портала существ: N. Они останутся в мире назначения. Закрыть?»; наблюдатель → «Внутри портала наблюдатель. Закрыть?» (оба → одно подтверждение с обоими) |
| `sendObserver`    | closed → «Нельзя отправить наблюдателя в закрытый портал.»; критический риск → «Риск критический (N из 100). Отправлять наблюдателя запрещено регламентом.»; уже отправлен → «Наблюдатель уже находится внутри.» | — |
| `toggleQuestioned`| closed → «Портал закрыт — пометка не имеет смысла.»       | —             |

## Эффекты действий (`src/domain/reducer.ts`)

- `stabilize` → `stability = min(100, +25)`, `energy = max(0, -10)`
- `close` → `status = 'closed'`
- `sendObserver` → `observerSent = true`
- `toggleQuestioned` → `open ↔ questioned`

Каждое разрешённое действие → запись `kind:'action'` в общий журнал **и** запись в
`history` портала. Запрещённое действие → портал не меняется, запись `kind:'blocked'`
с текстом причины.

- `advanceHour(state)` — у всех незакрытых порталов `hoursToCollapse = max(0, -1)`,
  `stability -= 3` (не ниже 0); одна системная запись «Прошёл час»; порталы с
  `hoursToCollapse === 0` → `closed` + системная запись «Портал схлопнулся».
- `loadDataset(key)` — заменяет порталы набором, очищает журнал, пишет системную
  запись о загрузке.

## Рекомендации (`src/domain/recommend.ts`)

`recommendAction(portal)` → `{ text, action }`:

- closed → «Действий не требуется», `null`
- critical + существа → «Эвакуировать существ и закрыть портал», `close`
- critical → «Немедленно закрыть портал», `close`
- high → «Стабилизировать портал», `stabilize`
- medium + `!observerSent` → «Отправить наблюдателя», `sendObserver`
- medium → «Продолжать наблюдение», `null`
- low → «Оставить открытым», `null`

## Архитектурные решения

- **Доменный слой без React.** `src/domain/*` — чистые функции, ничего не знают о
  React/DOM. Тестируются в среде `node`.
- **Проверка правил живёт в reducer, а не только в UI.** Интерфейс не может
  обойти запрет; запрещённые действия кликабельны и логируются.
- **Состояние только в памяти.** Нет localStorage, нет бэкенда, нет сети.
- **Время не тикает само.** Часы двигаются только через `advanceHour`.
- **Демо-данные детерминированы.** Без `Date.now()` и без случайных чисел в
  `datasets.ts` — демо воспроизводимо. `Date.now()`/счётчик id — только в reducer
  для runtime-записей журнала.
- **Никаких секретов.** Ни API-ключей, ни `.env` — они здесь не нужны вообще.

## Правила кода

- TypeScript строгий (`strict`, `noUncheckedIndexedAccess`, `noUnusedLocals` и т.д.).
- Доменная логика — чистыми функциями, без побочных эффектов (кроме id/времени в reducer).
- Интерфейс — на русском; код, идентификаторы, коммиты — на английском.
- Коммиты — осмысленные, в повелительном наклонении, по ходу работы.
- Никаких лишних зависимостей.
